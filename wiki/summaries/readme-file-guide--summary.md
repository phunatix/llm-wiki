# How to Write a Good README File — Summary

**Author**: Hillary Nyakundi (freeCodeCamp)
**Source**: freecodecamp.org
**Date**: December 2021

## One-Paragraph Summary

A README is the first file someone sees in a project and should answer what, why, and how. Minimum sections: title, description, installation, usage, credits, license. Optional: badges, contribution guidelines, tests. The guide emphasizes that README writing is a learnable skill that improves engagement and helps projects stand out.

## Minimum Required Sections

1. **Project Title**: One sentence describing the project
2. **Description**: What it does, why you used those technologies, challenges faced
3. **Installation**: Step-by-step setup for local development
4. **Usage**: Instructions and examples; include screenshots
5. **Credits**: Collaborators, tutorials referenced
6. **License**: GPL and others; choosealicense.com for help

## Optional Enhancement Sections

- **Badges**: Auto-updating stats (shields.io)
- **Contributing**: Guidelines for open-source contributors
- **Tests**: Code examples showing how to run tests

## Key Principle

A README should answer: What was your motivation? Why did you build this? What problem does it solve? What makes it stand out?
