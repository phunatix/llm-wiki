# Johnny.Decimal System

## Definition

The **Johnny.Decimal (JD) system** is a personal file organization framework that works like a personalized Dewey Decimal System. It assigns every file and folder a unique **number-based address** within a strict two-level hierarchy: **Areas** (broad categories, numbered 10–19, 20–29, etc.) and **Categories** within each area (numbered 11, 12, 13... within the 10–19 range).

Every file in the system has an address like **10.23** (Area 10, Category 10, Item 23) — unique, memorable, and permanently stable.

---

## Core Philosophy

JD optimizes for **searchability** — the ability to go directly to where something *must be* without having to search or browse. The key insight: if every item has a pre-assigned location that never changes, you can memorize addresses the way you remember phone numbers or postal codes.

> "Taxes for 2023. That's 10.23." — Crystal Lee

The system deliberately limits the hierarchy to **two levels** (Area → Category) to prevent endless nesting. A maximum of 10 areas, 10 categories per area, enforces discipline.

---

## Key Features

- **The Index**: A reference document (often a spreadsheet or note) that maps JD numbers to what lives there. Acts as the "table of contents" for your file system. Useful for noting context that wouldn't fit in a filename (e.g., the car mechanic's phone number filed under "car maintenance").
- **Sequential, stable addresses**: Once assigned, a number doesn't change. Unlike PARA, items don't move between folders as context changes.
- **No ambiguity about where things go**: Everything has exactly one right place. Reduces the daily "where do I put this?" decision.

---

## Strengths

- Extremely fast retrieval once you've memorized the structure — no search required
- Works identically across any tool (Finder, Google Drive, Dropbox, Obsidian)
- The Index doubles as a reference note system for metadata that doesn't fit in filenames
- Low ongoing maintenance — you don't need to periodically reorganize
- Especially strong for *files* (PDFs, downloads, scanned documents, images) vs. *notes*

---

## Limitations

- **Static by design**: The same rigidity that makes it fast to retrieve makes it hard to adapt. As your life changes, the structure resists change.
- **Doesn't address note-taking**: JD is a file system framework, not a note-taking methodology. It doesn't have opinions about how notes link, evolve, or connect to each other.
- **Not everyone's mental model**: The numeric addressing system clicks for some and feels alien to others. Crystal Lee noted returning to JD *because* her brain prefers rigid location-based memory over PARA's contextual flexibility.
- **Risk of two systems**: Many JD users maintain separate personal and work hierarchies, creating a "where is 15?" ambiguity if numbers overlap.

---

## Hybrid Use Pattern

A pattern that multiple practitioners have landed on:
- **JD for files** (PDFs, receipts, project assets, downloads) — static, searchable, stable
- **PARA for notes** (Markdown, Obsidian, linked knowledge) — flexible, discoverable, active

This hybrid reflects a real difference: *files* are often reference artifacts you retrieve by location, while *notes* are active knowledge you want to encounter again in context.
